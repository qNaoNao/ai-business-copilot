# AI Business Copilot 工程化升级记录

日期：2026-10-05。定位：面向求职展示的本地单 Agent 经营分析应用，不是已上线的企业服务。

## 这次升级解决什么

此前版本已经有真实 SQL 指标、品类/SKU 下钻、多轮提问、图表、历史和报告。
这次保留这些能力，补充检索证据、执行状态、恢复机制和复现测试。
参考 EchoMind 的模块划分思路，但没有搬入、执行或公开其付费源码、文档、面经或简历模板。

| 新能力 | 实际实现 | 明确边界 |
|---|---|---|
| LangGraph 工作流 | retrieve → model/plan → tools → model → verify；SQLite 检查点 | 单 Agent，不是多 Agent；没有人为制造协作角色 |
| 恢复 | 中断后的节点继续；已完成 SQL 查询不重跑；保存选中的品类/SKU | API 返回与检查点提交之间的崩溃窗口不能保证只扣费一次 |
| 本地 RAG | BM25 + 多语言 MiniLM 向量 + RRF；分块、来源、版本、引用 | 六条短规则的小型知识库；并非企业级文档检索平台 |
| 检索降级 | 缺失/过期索引自动退到 BM25，并显示实际后端 | 不会把降级后的结果标成向量检索 |
| 证据规则检查 | 引用完整性、币种、部分因果表达、数字存在性提示 | 不能证明每个数字与指标正确对应，也不能保证所有幻觉被发现 |
| 成本与执行审计 | 实际模型 tokens、缓存输入、工具延迟、请求/调用预算 | 模型价格未配置时费用为空；预算不是固定金额承诺 |
| 免费演示 | 预设流程执行真实 SQL，保留图表、引用、历史、导出 | 页面明确标注非大模型生成；不宣称任意问题都能自动理解 |
| 可复现测试/CI | 合成数据库、模拟模型响应、恢复和网页测试、固定依赖 | GitHub Actions 需要用户推送后运行，本地成功不等于云端已成功 |

## 为什么选择这些模块

LangGraph 的价值是状态与节点级恢复，而不是简历上的框架名称。
原有经营工具仍与框架无关，通过白名单注册入口调用。
选择小型本地多语言嵌入模型，可以避免每次检索付费。
BM25 与向量结果通过 RRF 合并；来源引用包含文档 ID、块号和内容版本哈希。
知识文件改变会使旧向量索引失效，需要重新构建，避免旧索引配新内容。

查询到的知识被作为引用证据，而不是系统指令；模型只能使用已注册的六个只读工具。
这减少了风险，但不是对提示注入或错误业务推断的完备防护。

## 实际验收证据

1. 本地原电商数据库：68 项自动测试通过；原 7 个离线经营问题、17 项数字检查通过。
2. 新增 26 项测试包括合成 SQL 已知答案、只读数据库、非法参数、无关检索拒答、索引过期降级、
   模型 token 统计、请求预算、中断恢复、恢复不重复查询、数据快照变更拒绝、网页多轮与重新加载恢复。
3. 本次没有调用付费 OpenAI API；真实模型接口使用模拟响应验收。
4. 本地浏览器免费模式已执行品类→SKU、连续周趋势；网页显示真实工具结果和图表。
5. 锁定依赖在独立的无继承环境安装成功；不含私有 DB/Key/历史的源码副本共发现 68 项测试，
   57 项通过、11 项私有数据专用检查明确跳过，无失败。

新增测试不是对大模型回答准确率的测量，也不是压力测试、安全认证或真实业务收益验证。

## 检索实验

语料：六条人工整理的经营规则，当前每条一个块。用 24 条中英文人工标注查询：
开发集 8 条（6 相关 + 2 无关），留出集 16 条（12 相关 + 4 无关）。
这些查询和标签由项目自行编写，不是外部独立盲测或标准公开评测集。
同义词扩展、通用词过滤和相关性门槛属于启发式；不是训练出的概率。
门槛与通用词修正在开发例子上检查；不以反复调留出结果追求满分。

| 留出集指标 | 原关键词 | BM25 + 同义扩展 | BM25 + 本地向量 + RRF |
|---|---:|---:|---:|
| Hit@3（相关题命中任一标注文档） | 6/12 | 11/12 | 11/12 |
| MRR@3 | 0.5000 | 0.9167 | 0.9167 |
| 无关题正确不返回 | 4/4 | 4/4 | 4/4 |

向量版本在这个小语料上没有超过 BM25，不能包装成“向量检索显著提效”。
实测中位检索耗时约 0.4 ms / 0.04 ms / 5.2 ms（本机、预热后、单次小样本；非并发 SLA）。
原始结果包含每题输出和时间：[retrieval_results.json](evaluation/retrieval_results.json)。
Hit@3 是检索指标，不等于回答正确率；4 道无关题不是完整拒答能力的证明。

## 模型与费用边界

付费模式默认沿用项目的 gpt-5-mini，不擅自升级到昂贵模型。
每轮最多 6 次模型请求、6 次工具调用；每次输出最多 3500 tokens。
SDK 超时 45 秒、自动重试为 0。达到预算时返回 partial 状态并保留已完成证据。
这些是请求数量/输出长度限制，不是固定美元上限；多轮历史仍可能增加输入费用。
实际 tokens 取自接口；模型未返回 usage 时标为未知。
估算费用需用户提供当前模型的普通输入、缓存输入和输出单价，准确费用以账单为准。

付费模式使用 OpenAI 的 store=True/previous_response_id：用户问题、检索片段和工具结果会发送至 API。
免费模式不向模型 API 发送数据。公开部署前需要重新审核数据与存储政策。

## 当前水平与下一步

现在可以准确描述为“有真实分析工具、轻量 RAG、LangGraph 持久化和可复现验收的本地 AI 应用”。
比只演示一次聊天的入门作品更有工程证据；仍不能称为生产级系统或承诺其一定通过招聘筛选。
面试中真正有价值的是能说明：为什么用只读工具、为什么比较日均、恢复如何避免重复查询、
为什么向量没有跑赢 BM25，以及自动核验不能证明什么。

下一阶段优先补一个受控的在线演示/部署和更丰富的知识与失败案例。
不为“显得复杂”加入无业务需要的多 Agent、MCP、重排器或动态监控；若岗位明确要求再有针对性扩展。
